# 营销转码语义理解

模型不得参与最终制造码生成。模型只负责理解自然语言、保留原文证据、识别歧义；内部代码映射和制造码生成必须由已批准规则表与确定性规则引擎完成。

## 选择任务

- 处理客户CCL特殊规则时，任务类型使用 `rule_structure`，读取 `references/semantic-normalizer-prompt.txt`，并按 `references/semantic-normalizer.schema.json` 校验。
- 处理客户规格、品名、物料描述和订单备注时，任务类型使用 `order_normalization`，使用相同提示词和结构约束。
- 确定性规则引擎生成候选码后，证据审查任务使用 `evidence_review`，读取 `references/evidence-reviewer-prompt.txt`，并按 `references/evidence-review.schema.json` 校验。

## 执行语义标准化

1. 保留每一个输入列及其列名，不得先拼成无法追溯来源的一段文字。
2. 只处理CCL，不处理PP、PP小片、RC和含树脂百分比的订单。
3. 按客户代码或客户简称，只检索当前客户的相关规则。
4. 可由程序稳定识别的精确数字、单位和格式先交给确定性解析器。
5. 让模型分类自然语言条件，并逐字保留原文证据片段。
6. 使用固定结构和受控词表校验模型返回结果。
7. 拒绝模型编造的值、缺少原文证据的结论、完整制造码和未允许字段。
8. 合并模型语义和确定性解析事实；明确数值事实优先，冲突时进入人工复核。
9. 将标准语义交给已批准客户规则和辅助映射表处理。
10. 记录模型名称、提示词版本、输入摘要、原文证据、歧义和校验状态。

批量复核已知订单语义样本时，使用：

```bash
python model_skills/marketing-transcode-semantics/scripts/normalize_order_samples.py \
  --output /tmp/order-semantic-normalized.json
```

脚本只保存经过Schema校验的标准语义和原文证据，不保存或输出制造码。标准语义必须经过人工或正确码回归确认后，才能转换为`TAM-FIELD-MODEL-*`受控映射进入正式转码。

## 理解业务表达

- “备注中有X0A0/X0B0/car/汽车板/458/439字样”表示多个关键词任一命中，标准业务意图为汽车板。
- “备注中有MINILED字样”表示关键词命中，标准业务意图为MINILED。
- “NY1600及NY2140外，其余均下汽车板料号”表示排除集合：胶系不属于NY1600、NY2140时，业务意图为汽车板。
- “客户规格没有Q时”表示指定来源字段不包含Q，不能扩大为所有字段都没有Q。
- “订单若不备注芯厚，默认是总厚”表示缺失条件下的默认值，不是所有订单无条件按总厚。
- “第5码A或S”表示物料号或备注的字符位置条件，模型识别语义，程序执行字符位置判断。
- 原文明确写出的AC、AM等值，只能原样放在 `stated_target_value`，后续仍需内部代码表校验。

## 执行边界

- 不得输出最终制造码或候选制造码。
- 不得创造原文和已批准字典中不存在的胶系、等级、铜厚、尺寸、厚度或总芯厚映射。
- RV/3H等多值规则如果没有选择条件或业务反馈，不得自行选择。
- 不得推测未提供的订单备注；必须记录到 `missing_inputs`。
- 当前22码不处理组合结构、铜箔厂商、玻布厂商和配方代码。
- 模型置信度只作为参考，最终校验和评分由程序负责。

## 审查候选码证据

1. 分别审查胶系、厚度、铜箔规格、尺寸、胶水类别、铜箔类型、基板级别和总/芯厚八个字段。
2. 对照原始字段、标准语义、已批准规则和辅助映射命中记录。
3. 每个字段只能返回：支持、矛盾、歧义、缺少证据四类结论，对应结构值为 `supported`、`contradicted`、`ambiguous`、`missing_evidence`。
4. 模型不得直接给最终数字分数，程序将审查结论转换为受限的加减分。
5. 候选字段依赖订单备注等输入但实际未提供时，必须判定为缺少证据。

## 程序评分矩阵

- P2-3A先由程序按 `references/evidence_score_matrix.json` 生成影子分数，不调用模型。
- `supported` 保留现有字段分；已批准语义规则与候选值完全一致时可提高到98分。
- `contradicted` 固定为0分，`ambiguous` 最高80分，`missing_evidence` 最高60分。
- 默认规则、默认常规铜和通用阈值只能判定为歧义，不能仅凭默认值成为高置信证据。
- 八个门禁字段的影子总分仍取字段最低分；影子分数不得覆盖正式分数和当前90分门禁。
- P2-3B接入模型时，模型只审查程序无法确定的字段，并继续返回四类受控结论，不直接返回数字分数。
- P2-3B只调用存在相关已批准语义规则ID的歧义或缺证据字段，普通默认字段不得批量调用模型。
- `TRANSCODE_EVIDENCE_MODEL_MODE=shadow` 才允许调用，默认 `off`；单任务调用上限默认50。
- 只有 `high` 置信度模型结论可进入影子分数；中低置信度只记录，不替换程序结论。
- 正式证据门禁默认 `enforce`，有效分取确定性分和证据分的较低值；可用 `TRANSCODE_EVIDENCE_GATE_MODE=shadow` 一键回滚为只观察。

## 失败处理

- 模型超时、返回内容不符合结构、证据校验失败或模型不可用时，确定性转码链路仍应继续运行。
- 模型失败不能提高默认字段的分数。
- 关键语义规则依赖的输入缺失时，候选码必须进入待确认。
