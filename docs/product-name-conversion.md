# 新品名转换（第一期）

## 范围

- `/product-names/board` 与 `/product-names/pp`：转换工作台、基础映射、编码规则、个人转换记录。
- 独立新品名引擎，不调用旧02/03转码规则，也不继承客户特殊规则。
- 胶系主表初始化自用户提供的 `_ 胶系主表维护view20260724092307.xlsx`（Sheet1，282条），两种新品名产品共用这份新版主表。源数据随代码保存在 `default_rules/product_names/glue.json`。
- 其他种子字典来源为 `厂内新PP_基板_PP小片转码规则.docx`。只包含文档明确枚举的数据，未展开“……”及未给出值的通配等级。
- 旧订单模块 `automation_adhesive_codes` 保持不变；新品名主表目前不自动反写它。两者并非同一维护入口，后续如需合并必须单独迁移核验。

## 使用及边界

1. 入口仅客户、客户规格和特殊要求三项。基于本地确定性识别（非AI）拆解，调用新版映射生成预览；未确认不写转换记录。
2. 分段支持可输入下拉选项。胶系匹配型号后，未注明配方、用途采用通用N并标记确认；不从旧编号推断。缺失与冲突由业务修正。修改通过服务端同一编码引擎实时校验，成功后才能确认保存。
3. 基板26位；PP与PP小片25位；生成成功保存输入、分段结果、所用映射及其版本快照。
4. 只有管理员能维护映射；登录业务人员可查询、转换并查看自己的历史。
5. 保存即时生效，无草稿/审批/发布状态。编码不可重命名，停用代替删除；历史快照不随当前映射更新。
6. 固定字段顺序与长度为只读标准；可变编码取值通过基础映射维护。不开放任意公式/脚本执行。
7. 映射details新增aliases（|分隔文字，非正则表达式）、default_for（board/pp/board,pp/空）。未维护的标准默认：C3、结构A、玻布C、PP品规XX、印字W、品级A0，全部显示默认提示；保存为空即取消该默认。多默认同时命中不取第一条，提示冲突。
8. 基础识别支持胶系型号、mm/mil厚度、标准双面铜箔、玻布、RC/微米厚度、片料尺寸及维护的卷料码。尚非任意自然语言解析；特殊要求参与基础提取但不代表所有要求均已编码，须业务确认。
9. 客户字段仅随记录留存，本期不执行客户专属规则。通过独立品名转换菜单进入，不替换旧Agent入口。

## 已知待补标准

- H未出现在铜重枚举中，因此不自动推定H对应多少oz；文档明确的完整HHNN、H1RN等组合独立作为标准双面组合可选。
- 大厚度A前缀适用边界不完整，本期不编码大于等于10mm的厚度。
- PP自用厚度与RC之间未明确范围、特殊客户厚度以及未定义的品规等级不猜测。
- 尺寸精度超限不自动舍入；单边编码4位，卷料只用标准尺寸映射。
- 不含客户特殊下单备注映射、特殊规则覆盖、Excel批量任务、直接修改现有订单接口。

## 存储及部署

沿用平台 `db_cursor` 路由：PostgreSQL平台使用服务器数据库；测试/旧部署支持SQLite。
增量SQL：`migrations/automation/postgresql/0014_product_names.sql`。
三个新表：`product_name_mappings`、`product_name_audit`、`product_name_results`。

启用 `APP_STARTUP_MAINTENANCE_ENABLED` 时启动自动创建新表并补齐缺少的标准记录，永不覆盖已有记录。共享数据库的非维护节点不执行DDL，应先由维护节点执行一次：

```sh
.venv/bin/python -m flask --app fangzheng_web_app:create_app product_names init-db
```

保存采用版本条件更新；检测到其他人修改返回冲突提示，审计和映射更新同一事务提交。转换一次读取当时启用映射并保存快照。没有进程内规则缓存，后续请求读取最新已提交数据。
删除/停用种子注意：请使用停用；初始化只补缺少的键，不会重新启用已停用记录。
