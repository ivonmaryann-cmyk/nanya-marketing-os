# 营销转码 Agent 规则配置页面维护 SOP

更新时间：2026-08-03

## 一、入口和适用范围

从“营销转码 Agent”页面右上角进入“规则配置”。所有业务规则只有一个入口，进入后按以下分类维护：

1. 基础规则：全部客户共用的胶系、厚度、铜箔、尺寸、胶水类别、铜箔类型、基板级别、总/芯厚规则。
2. 客户特殊规则：按客户维护八类 CCL 特殊要求。
3. 订单备注语义：维护“下汽车板”“需要AP板”等业务说法及其标准结果。
4. 出码与人工确认：维护评分说明和需要人工确认的业务条件。
5. 备份与修改记录：查看每天自动备份、手动备份、历史修改和恢复入口。

组合结构、铜箔厂商、玻布厂商和配方代码当前不纳入转码规则维护。

## 二、基础规则维护

### 条件规则

用于表达“满足哪些条件时，某个参数应输出什么结果”。填写时应遵循：

1. 一条规则只调整一个参数。
2. 只填写业务已经明确的条件；没有条件的项目保持为空。
3. 多个条件同时填写时，必须同时满足才生效。
4. 保存后立即生效；停用后立即停止使用。

### 标准映射

用于维护稳定的一对一对应关系，例如胶系名称对应场内胶系代码、等级说明对应基板级别代码。页面调整值优先于系统内置值，原系统值仍保留作为回退基线。

2026-08-03起，该分类与运行引擎使用同一份数据，包含：最新胶系代码、胶系类别、合法基板级别、等级触发词、标准尺寸、高频MIL、铜箔微米/类型/规格、尺寸区间和总芯厚转换。页面修改保存后立即进入Agent运行时，不改写原Excel。

### 客户与算法规则

用于查看和维护原来隐藏在Agent辅助映射表中的规则，包含胶系主表、兼容别名、选择条件、基础条件、客户尺寸/单边尺寸/尺寸算法、客户厚度、物料编码口径、外部尺寸表引用和待接入规则。业务人员只需按页面中文字段维护，无需理解JSON或Python参数。

## 三、客户特殊规则维护

1. 先选择客户，再选择需要维护的参数分类。
2. 客户代码、客户简称和适用条件应尽量完整，避免不同客户误命中。
3. 每条规则只维护一个标准输出结果。
4. 订单备注条件只在订单备注有内容并命中时覆盖；没有订单备注时继续执行基础规则和客户其他确定性规则。
5. 保存、停用和恢复都会写入修改记录。

## 四、订单备注语义维护

1. 维护的是业务说法与标准意图的对应关系，不由模型直接生成制造码。
2. 原文明确命中已确认规则时，可作为确定性规则执行。
3. 口语、错别字或近义表达经过模型标准化后，只能绑定页面已有规则，不能创造新规则。
4. 模型辅助结果不能单独达到正式出码标准；存在歧义时进入人工确认。

## 五、评分与正式出码

1. 正式出码门槛固定为100分，页面不可降低。
2. 八个关键参数必须全部达到100分，并且不存在规则冲突、条件不足、多值不唯一或基础字段缺失。
3. 结构码当前为占位符，只记录，不参与置信度评分和正式出码拦截。
4. 业务明确且经过验证的基础规则、客户规则和原文直接命中的订单规则可以取得100分。
5. 模型辅助、模糊语义、缺少证据或规则冲突不能取得100分，必须进入人工确认。
6. 人工确认只来源于规则本身的不确定性；测试文件中的正确码和结果对比不参与页面评分。

## 六、备份和恢复

1. 系统每天自动生成一次完整页面配置备份。
2. 自动保留最近30天，超过30天的备份自动清理。
3. 重大批量修改前可手动备份。
4. 恢复某个备份前，系统会先自动备份当前配置。
5. 恢复操作会覆盖页面维护层，系统内置Excel基线不会被改写。

## 七、日常维护建议

1. 新规则先用一条经典规格验证，再使用10条代表性数据回归。
2. 同一业务条件出现多个输出时，不要强行保存唯一结果，应转为人工确认条件并补充业务口径。
3. 修改客户规则时核对客户简称及别名，防止同公司不同简称漏命中。
4. 每次修改后在“修改记录”确认修改人、时间、分类和结果。
5. 页面规则异常时先恢复最近正常备份，再由开发人员核查，不直接修改底层Excel或Python代码。

## 八、技术边界

页面维护层优先于系统基线，但营销转码 Agent 仍是唯一规则引擎。基础Excel、已发布Agent资产和代码规则继续作为只读基线及兼容回退；无订单库存等其他模块只能调用Agent接口，不复制规则。
