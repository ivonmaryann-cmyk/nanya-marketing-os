# 客户特殊规则结构化草稿_按原表行_20260707：Agent 识别规则表设计说明

日期：2026-07-08
适用文件：`客户特殊规则结构化草稿_按原表行_20260707.xlsx`
适用范围：营销转码 Agent 的客户特殊需求规则读取、字段映射、规则执行、规则解释与后续规则表生成。

---

## 1. 目标说明

`客户特殊规则结构化草稿_按原表行_20260707.xlsx` 是业务原始客户特殊需求表转换后的结构化草稿，主要用于业务确认和规则整理。

它不是最终给 Agent 直接执行的规则表。

最终应从该草稿中提取可执行内容，生成一张 Agent 专用客户特殊需求规则表，用于营销转码 Agent 识别客户特殊规则、命中特殊规则、覆盖标准转码字段，并输出可解释的命中依据。

整体链路如下：

```text
客户特殊规则结构化草稿_按原表行_20260707.xlsx
    ↓
读取可执行草稿行
    ↓
字段过滤
    ↓
规则拆分
    ↓
字段映射
    ↓
值映射与字典校验
    ↓
生成 Agent 客户特殊需求规则表
    ↓
营销转码 Agent / 规则引擎读取执行
```

---

## 2. 基本原则

### 2.1 草稿表给人看，Agent 规则表给机器执行

当前草稿表保留“一客户一行”，适合业务人员确认。

最终 Agent 规则表建议变为“一条规则一行”，适合程序执行。

例如一个客户在草稿表中可能有多条规则：

```text
胶系规则
基板厚度规则
铜箔规格规则
基板尺寸规则
基板级别规则
总/芯厚规则
```

最终给 Agent 执行时，应拆成多条原子规则。

---

### 2.2 Agent 不直接读取原始长文本执行

Agent 不应直接读取以下内容作为执行规则：

```text
原始 CCL特殊规则长文本
原始 通用特殊规则长文本
PP特殊规则
PP小片特殊规则
非影响转码备注
不纳入本次转码说明
组合结构
铜箔厂商
玻布厂商
配方代码
订单语义规则
排版结构/布号映射
```

这些内容可保留用于追溯、参考、人工确认或后续模块设计，但不应直接进入当前 Agent 执行层。

---

### 2.3 当前 Agent 只处理当前转码需要的字段

当前营销转码 Agent 只关注会直接影响当前 CCL 品名转码的字段：

```text
胶系
基板厚度
铜箔规格
基板尺寸
胶水类别
铜箔类型+印字/非印字
基板级别
总/芯厚
```

不进入当前 Agent 执行规则的字段：

```text
组合结构
铜箔厂商
玻布厂商
配方代码
PP规则
PP小片规则
订单语义规则
排版结构/布号映射
```

## 3. Agent 应读取的草稿表字段

从 `客户特殊规则结构化草稿_按原表行_20260707.xlsx` 生成 Agent 规则表时，建议只读取以下字段。

| 字段 | 是否读取 | 用途 |
|---|---|---|
| 客户代码 | 是 | 客户精确匹配主键 |
| 业务员 | 是 | 规则追溯，不作为主要执行条件 |
| 客户简称 | 是 | 人工识别和辅助展示 |
| 下单员 | 是 | 规则追溯 |
| 来源行号 | 是 | 回溯业务原表行 |
| 通用特殊规则 | 是 | 原文留底，不直接执行 |
| CCL特殊规则 | 是 | 原文留底，不直接执行 |
| 通用特殊规则_结构化 | 是 | 生成 Agent 规则的来源之一 |
| CCL特殊规则_结构化 | 是 | 生成 Agent 规则的主要来源 |
| 业务反馈 | 是 | 最高可信来源，用于覆盖原始规则歧义 |
| 结构化处理状态 | 是 | 判断是否进入 Agent 规则生成 |
| 不纳入本次转码说明 | 是 | 保留排除原因，不生成执行规则 |
| 非影响转码备注 | 可读但不执行 | 只作为参考，不进入执行规则 |

不建议读取以下字段作为 Agent 执行规则来源：

| 字段 | 原因 |
|---|---|
| PP特殊规则 | 当前不处理 PP |
| PP小片特殊规则 | 当前不处理 PP小片 |
| 非影响转码备注_结构化 | 不执行，容易误导 Agent |
| 待确认点 | 当前不作为规则输入 |
| 本轮复核分类 | 可作为历史记录，不作为执行输入 |
| 本轮复核说明 | 可合并到规则来源说明 |
| 本轮复核依据 | 可合并到规则来源说明 |
| 本轮复核时间 | 可作为日志，不作为执行输入 |

## 4. 哪些草稿行可以生成 Agent 执行规则

Agent 只应从以下状态生成执行规则：

```text
结构化处理状态 = 可执行草稿
```

其他状态处理方式：

| 草稿状态 | Agent 处理 |
|---|---|
| 可执行草稿 | 可以生成 Agent 执行规则 |
| 技术待支持 | 暂不执行，可进入技术待办 |
| 不纳入 | 不生成执行规则 |
| 无规则 | 不生成执行规则 |

执行层只读取：

```text
enabled = TRUE
status = approved
```

建议从草稿生成最终表时，先把 `可执行草稿` 转为候选 `approved` 规则；其他状态不进入执行规则表。

## 6. 最终 Agent 规则字段说明

### 6.1 规则身份字段

| 字段 | 含义 | 示例 |
|---|---|---|
| rule_id | 每条规则唯一编号 | CSR-000001 |
| enabled | 是否启用 | TRUE |
| status | 规则状态 | approved |
| priority | 执行优先级 | 10 |
| version | 规则版本 | 20260708 |

---

### 6.2 客户匹配字段

| 字段 | 含义 | 执行建议 |
|---|---|---|
| customer_code | 客户代码 | 作为客户规则匹配主键 |
| customer_name | 客户简称 | 用于展示和辅助核对 |
| sales_name | 业务员 | 用于追溯 |
| order_user | 下单员 | 用于追溯 |

规则执行时优先级：

```text
客户代码精确匹配 > 客户简称辅助匹配 > 业务员/下单员追溯
```

---

### 6.3 物料范围字段

| material_scope | 含义 | 当前是否启用 |
|---|---|---|
| ALL | 通用特殊规则，适用于该客户全部物料 | 是 |
| CCL | CCL特殊规则，适用于基板/覆铜板 | 是 |
| PP | PP规则 | 否 |
| PP_SHEET | PP小片规则 | 否 |

当前阶段只建议启用：

```text
ALL
CCL
```

---

### 6.4 来源解释字段

| 字段 | 含义 |
|---|---|
| source_row | 来源行号 |
| source_column | 来源列，例如 CCL特殊规则_结构化 |
| source_text | 规则原文或结构化原文 |
| business_feedback | 业务反馈 |
| rule_explanation | Agent 输出解释 |

来源解释字段必须保留。

示例解释：

```text
命中客户特殊规则：客户 103891 方正F7，来源 CCL特殊规则，原文“基板厚度：全部是芯厚”，所以总/芯厚代码 tc_code=C。
```

## 7. 支持的 rule_type

建议最终 Agent 规则表支持以下规则类型。

| rule_type | 含义 | 示例 | 当前建议 |
|---|---|---|---|
| mapping | A 转 B | NY2150 -> 2B | 启用 |
| default_set | 默认赋值 | 全部芯厚 -> tc_code=C | 启用 |
| conditional_set | 满足条件时赋值 | 当胶系=NY2150时 grade_code=AC | 启用 |
| range_rule | 范围判断 | 厚度 <0.9 -> AC | 启用 |
| size_mapping | 尺寸映射 | 37*49 -> 37.3*49.3 | 视技术能力启用 |
| external_lookup | 外部表查找 | 健鼎/超颖板厚表 | 后续启用 |
| reference_only | 只参考，不执行 | 非影响转码备注 | 不进入执行 |
| technical_pending | 技术待支持 | 单边尺寸映射 | 不进入执行 |

当前第一版建议只执行：

```text
mapping
default_set
conditional_set
range_rule
```

## 11. 规则优先级

当前确认的执行优先级：

```text
客户订单明示 > CCL特殊规则 > 通用特殊规则 > 普通规则 > 默认规则
```

建议 priority 设置：

| 来源 | priority | 说明 |
|---|---:|---|
| 客户订单明示 | 0 | 订单明确写出的要求最高 |
| CCL特殊规则 | 10 | CCL 专用客户规则 |
| 通用特殊规则 | 20 | 客户通用规则 |
| 普通规则 | 50 | 标准编码规则 |
| 默认规则 | 90 | 系统默认兜底规则 |

如果同一字段发生冲突，执行优先级更高的规则。

示例：

```text
通用规则：默认总厚
CCL规则：全部芯厚
```

执行结果：

```text
按 CCL特殊规则执行，tc_code=C
```

## 12. 业务反馈优先级

业务反馈列作为最高可信来源。

推荐来源可信顺序：

```text
业务反馈 > 新格式业务原文 > 旧特殊需求 Sheet > 当前代码逻辑 > 模型推断
```

例如：

```text
原始规则：NY3150HC=RV/3H
业务反馈：选择 RV
```

最终 Agent 规则应生成：

```text
condition_glue=NY3150HC
target_field=glue_code
target_value=RV
source_text=NY3150HC=RV/3H
business_feedback=选择 RV
```

不应继续保留 `RV/3H` 多值待确认。

## 13. Agent 规则执行流程

建议执行流程：

```text
1. 读取 Agent 客户特殊需求规则表
2. 只加载 enabled=TRUE 且 status=approved 的规则
3. 按 customer_code 建索引
4. 根据订单客户代码匹配客户规则
5. 根据 material_scope 过滤规则
6. 按 priority 从高到低排序
7. 判断 condition 是否命中
8. 命中后执行 target_field=target_value
9. 记录 before_value / after_value / source_text / rule_explanation
10. 输出转码结果和命中解释
```

执行时不能让模型直接生成最终编码。

最终编码仍应由规则引擎根据确定字段生成。

## 16. 草稿到 Agent 表的转换流程

建议转换流程：

```text
1. 读取 客户特殊规则结构化草稿_按原表行_20260707.xlsx
2. 过滤 结构化处理状态=可执行草稿
3. 读取 通用特殊规则_结构化 和 CCL特殊规则_结构化
4. 按结构化文本拆分为原子规则
5. 丢弃非当前字段范围的规则
6. 中文业务字段映射为 Agent 字段
7. 业务值映射为系统代码
8. 条件文本解析为结构化条件
9. 校验 target_field 是否允许执行
10. 校验 target_value 是否存在于字典
11. 生成 rule_id、priority、source_text、rule_explanation
12. 输出 agent_customer_special_rules
```

## 17. 校验规则

生成 Agent 规则表后，必须做校验。

### 17.1 字段校验

`target_field` 必须属于当前启用字段：

```text
glue_code
thickness_rule
thickness_code
copper_code
size_code
glue_category_code
copper_type_code
grade_code
tc_code
```

如果出现以下字段，直接拒绝进入执行表：

```text
struct_code
copper_vendor_code
glass_vendor_code
formula_code
pp_rule
pp_sheet_rule
order_semantic_rule
```

---

### 17.2 值校验

`target_value` 必须通过字典校验：

| target_field | 校验来源 |
|---|---|
| glue_code | 胶系代码表 / 客户胶系映射表 |
| copper_code | 编码规则 / 铜箔规格规则 |
| size_code | 尺寸编码规则 / 特殊尺寸规则 |
| copper_type_code | 铜箔类型规则 |
| grade_code | 编码规则 / 基板级别规则 |
| tc_code | 只能是 C 或 T |
| glue_category_code | 胶水类别规则 |
| thickness_rule / thickness_code | 厚度规则 / 总芯厚转换规则 |

---

### 17.3 冲突校验

如果同一客户、同一物料范围、同一条件、同一字段出现多个不同值，需要按优先级判断。

如果优先级相同但值不同，应进入人工复核。

示例：

```text
规则1：客户A + CCL + NY2150 -> grade_code=A1
规则2：客户A + CCL + NY2150 -> grade_code=AC
```

如果没有优先级或业务反馈解释，则不能自动执行。

## 21. 结论

`客户特殊规则结构化草稿_按原表行_20260707.xlsx` 是业务确认和结构化整理用表。

真正给 Agent 识别和执行时，不应直接读取整张草稿表，而应生成一张 Agent 专用客户特殊需求规则表。

最终 Agent 表应具备以下特点：

```text
一条规则一行
只读取可执行草稿
只保留当前 CCL 转码需要的字段
中文字段映射为系统字段
业务值映射为系统代码
规则条件结构化
保留来源解释
通过字典校验
按优先级执行
不让模型直接生成最终编码
```

当前最重要的原则是：

```text
草稿表给人确认，Agent 表给机器执行。
Agent 只读取结构化、可执行、已映射、可校验的规则。
```
