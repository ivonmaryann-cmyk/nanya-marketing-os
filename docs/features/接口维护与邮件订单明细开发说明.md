## 数据留痕

每个订单模板保存以下追加式记录：

1. 流程记录：首次提取、重新提取、模板保存、后续 Mock/真实接口调用。
2. 数据变更：表头及每条明细的字段变更前值、后值、行号和保存时点。
3. 接口交互：接口键、配置版本、Mock 标识、状态、耗时、脱敏请求与响应、失败信息。

料号查询结果以独立建议记录保存，不能覆盖业务人员手工编辑的产品编号、品名等字段。

## 接口维护

初始提供两个配置：

| 接口 | 当前能力 |
| --- | --- |
| 批量料号查询 | 支持 Mock 配置与批量请求/响应结构；已具备写入订单交互日志和查询建议的服务能力。 |
| 内销录单 | 支持配置维护与 Mock 场景配置；等待业务确认录单接口报文后再开放人工提交。 |

每个配置可维护 Mock/真实模式、请求方法、完整请求地址、入参映射、出参映射及四类 Mock 场景（成功、未找到、业务错误、超时）。完整请求地址包含协议、端口（如有）和路径。

配置页提供“接口测试”按钮：Mock 模式直接返回 Mock 测试结果；真实接口模式直接请求当前表单中的完整地址，并显示状态码、耗时和响应摘要。为避免异常接口长期占用请求，后台固定采用 15 秒保护时间，不向页面暴露超时设置。

## 数据库

- SQLite 初始化同步创建接口配置、配置版本、订单明细事件、接口调用日志和料号查询建议表。
- PostgreSQL 新增迁移：migrations/automation/postgresql/0006_order_interface_maintenance.sql。
- 上线 PostgreSQL 前必须先执行该迁移；接口配置不存储明文密码或 Token，日志只保留脱敏业务报文。
