# PP转码Agent功能需求文档

- 文档状态：第一、二、三阶段主体已完成，待补充首批客户特殊规则
- 版本：v0.5
- 更新日期：2026-08-12
- 适用模块：PP转码Agent
- 页面入口：功能中心 -> PP转码Agent

## 1. 建设目标

PP转码Agent用于将客户提供的PP（半固化片）规格转换为27位场内PP品名，并提供逐码段的证据、规则命中记录和人工确认能力。

本模块以**页面维护的规则为唯一生效来源**。业务后续新增、修改、停用规则均在页面完成；代码只负责解析、规则匹配、编码拼接、评分、权限、备份和追溯，不承载业务映射。

旧文件[编码规则(老).xlsx]仅用于首次初始化和业务核对，不作为运行时规则源，也不作为后续日常维护入口。

## 2. 范围与边界

### 本期范围

- 独立功能入口和PP转码页面。
- 单条与批量PP规格转码，二者共用同一套PP规则计算函数。
- PP基础规则、PP客户特殊规则、固定默认占位规则的可视化维护。
- 27位PP编码生成、字段证据、待人工确认、任务记录和下载结果。
- 页面规则保存后立即生效；每日自动备份，保留30天；保留修改记录。

### 不在本期范围

- 不修改现有CCL营销转码Agent的客户规则、页面或结果。
- PP仅共享营销转码Agent当前活动版本的胶系主表和兼容别名；PP其他规则与CCL规则隔离。
- 不根据历史品名或模型猜测未明确的PP字段值。
- 不自动回写APS、订单、报价或其他业务系统。
- 不以旧Excel作为业务人员的日常维护入口。

## 3. PP编码规范

PP编码固定为27位，按下表拼接：

| 码位 | 字段 | 来源与规则 |
| --- | --- | --- |
| 1-2 | 胶系 | 直接使用营销转码Agent当前活动版本的胶系主表和兼容别名；PP页面只读，不重复维护。 |
| 3-6 | 玻布规格 | 客户规格直接识别并格式化为4位，例如`106 -> 0106`。 |
| 7-10 | PP长度(M) | 客户规格直接识别，例如`350M`、`050M`。 |
| 11 | 配方类别 | 基础规则维护；使用胶系对应的PP配方类别，例如`R`、`Y`。 |
| 12-14 | 树脂含量 | 客户规格直接识别并标准化，例如`42% -> 420`。 |
| 15-16 | 玻布厂家 | 客户特殊规则；未维护时固定输出`**`。 |
| 17 | PP级别 | 客户特殊规则；未维护时固定输出`*`。 |
| 18 | PP窄幅 | 客户特殊规则；未维护时固定输出`*`。 |
| 19-21 | 客户码 | 客户特殊规则；未维护时固定输出`***`。 |
| 22-24 | GT长短秒 | 客户特殊规则；未维护时固定输出`***`。 |
| 25-26 | 客户产品码 | 客户特殊规则；未维护时固定输出`**`。 |
| 27 | 配方代码 | 客户特殊规则；未维护时固定输出`*`。 |

占位符规则：未匹配或未维护的字段按该字段码位长度输出同数量的`*`。占位符表示“无明确规则”，不可被系统视为已确认业务值。

## 4. 规则体系

### 4.1 PP基础规则

基础规则仅允许维护全局、明确、一对一的对应关系。业务维护的是“识别到什么，输出什么”，不维护客户条件、口语描述或复杂优先级。

| 基础规则分类 | 示例 | 输出字段 |
| --- | --- | --- |
| 胶系编码 | 共享营销转码Agent当前胶系映射，例如`NY2150 -> 2B` | 第1-2码 |
| 玻布规格格式 | `106 -> 0106` | 第3-6码 |
| PP长度格式 | `50M -> 050M` | 第7-10码 |
| 配方类别 | `NY2150 -> R` | 第11码 |
| 树脂含量格式 | `42% -> 420` | 第12-14码 |

基础规则页面不出现“客户”“订单备注”“条件优先级”等字段。无法一对一确定的规则不得放入基础规则。胶系页只读展示营销转码Agent当前胶系主表和兼容别名，并提供统一维护入口；PP不保存胶系副本。

### 4.2 PP客户特殊规则

客户特殊规则按客户维度维护，也可明确标记为“适用全部客户”。它承接客户特有要求和存在条件判断的规则。

可维护目标字段：玻布厂家、PP级别、PP窄幅、客户码、GT长短秒、客户产品码、配方代码。

每条规则采用固定格式：

```text
当【客户】为……，且【胶系/玻布规格/PP长度/树脂含量/规格关键词/订单备注】满足……时，
将【目标字段】输出为……。
```

示例：

```text
当客户为南通深南，胶系为NY2150，玻布规格为106，树脂含量为42%时，PP级别输出C。
```

页面通过字段下拉框、判断方式下拉框和结果输入框维护；不向业务展示数据库字段名、程序表达式或代码优先级。

### 4.3 固定默认占位规则

默认占位规则属于编码规范，页面只读展示，不需要业务重复新增：

- 玻布厂家未命中：`**`
- PP级别未命中：`*`
- PP窄幅未命中：`*`
- 客户码未命中：`***`
- GT长短秒未命中：`***`
- 客户产品码未命中：`**`
- 配方代码未命中：`*`

## 5. 页面设计

### 5.1 功能中心入口

新增`PP转码Agent`卡片，与营销转码Agent并列。卡片说明：

> 将客户PP规格转换为27位场内PP品名；规则由业务在页面维护，未明确字段按码位星号占位并进入人工确认。

### 5.2 PP转码首页

页面包含：

1. 单条PP转码：客户代码、客户简称、客户规格、订单备注；提交后创建单行任务。
2. 批量PP转码：上传Excel后创建批量任务。
3. 当前状态：单条和批量共用任务状态、处理日志及确认入口，不在首页建立第二套临时转码逻辑。
4. 最近任务：统一展示单条和批量任务、状态、确认入口和下载入口。
5. 工具入口：PP规则配置、模型配置（如后续启用订单备注语义标准化）。

### 5.3 PP确认中心

确认中心交互与营销转码Agent保持一致：

- 左侧按“全部、待确认、已确认、暂不处理”筛选并逐条选择记录。
- 右侧只展示当前记录的客户规格、订单备注、27位待确认码、字段识别依据和处理动作。
- 支持上一条、下一条、本次确认、暂不处理；任务完成后仍可查看确认历史。
- 只有业务明确勾选并填写依据时，才将本次处理保存为长期PP客户特殊规则。

### 5.4 PP规则配置

独立入口`PP规则配置`，包含以下一级页签：

| 页签 | 内容 |
| --- | --- |
| 规则总览 | 基础规则、客户特殊规则、待确认规则的数量与查询入口。 |
| 基础规则 | 胶系、玻布规格、PP长度、配方类别、树脂含量五类一对一规则。 |
| 客户特殊规则 | 按客户查看、搜索、新增、编辑和停用PP客户规则。 |
| 出码与人工确认 | 27位完整性、评分门禁、人工确认说明。 |
| 备份与修改记录 | 查看每日备份及页面修改记录。 |

基础规则和客户特殊规则均支持：关键词搜索、状态下拉筛选、字段分类筛选、分页、编辑和停用。列表的编辑入口使用明确的“编辑”文字操作，不使用整行点击进入编辑。

## 6. 转码流程

```mermaid
flowchart LR
    A[输入客户与PP规格] --> B[识别为PP物料]
    B --> C[解析胶系、玻布、长度、RC]
    C --> D[匹配PP基础规则]
    D --> E[匹配PP客户特殊规则]
    E --> F[补齐规范默认星号]
    F --> G[生成27位待人工确认码值及字段证据]
    G --> H[人工确认或暂不处理]
    H --> I[任务记录与下载]
```

“默认星号”不会被转换为虚假的业务值。首期所有PP结果均只生成待人工确认码值，不写入正式码；业务在确认中心核对后才能将该码用于后续业务动作。后续是否开放“全部字段明确后自动正式出码”，另行由业务确认。

## 7. 评分与人工确认

评分沿用现有Agent“字段证据评分”原则，但PP单独维护字段范围。首期评分只用于提示字段确定性和人工排查，不作为自动正式出码门禁。

| 情况 | 字段分数 | 结果处理 |
| --- | ---:| --- |
| 命中已确认基础规则或已确认客户特殊规则 | 100 | 作为待人工确认码值的可靠字段证据。 |
| 客户规格直接识别且格式校验通过 | 100 | 作为待人工确认码值的可靠字段证据。 |
| 规范默认星号 | 仅记录 | 明确提示未维护字段及占位原因。 |
| 未维护但需业务判断的字段 | 小于100 | 生成待人工确认码值并提示缺失规则。 |
| 解析失败、规则冲突、格式不合法 | 0 | 不生成完整待确认码值，显示失败原因。 |

首期出码原则：不论评分是否达到100分，系统均不写入“正式码”；仅生成“待人工确认码值”。结构化证据、命中规则、占位原因都必须可查看。后续如业务确认自动正式出码的门禁口径，再单独启用。

人工确认只对当前任务生效。业务可显式勾选“同时保存为长期规则”后，才将本次确认转换为新的PP客户特殊规则；保存长期规则前必须填写业务依据。

## 8. 数据、备份与权限

### 数据边界

- PP除胶系映射外的基础规则、PP客户特殊规则、默认占位规范、任务和确认记录均独立于CCL规则数据。
- PP运行时共享营销转码Agent当前活动胶系主表和兼容别名，不继承其CCL客户、订单备注或关键词型胶系选择规则。
- 可复用现有规则存储、备份和审计基础设施，但必须以`物料类别=PP`隔离查询与运行。
- 不读取或覆盖CCL客户特殊规则；PP客户特殊规则仍在PP页面独立维护。

### 备份与追溯

- 页面每次保存记录修改人、时间、修改前后内容和业务依据。
- 系统每天生成一次规则备份，保留最近30天。
- 可查询历史修改，但本期不要求业务理解或操作“版本发布”。

### 权限

本期先与营销转码Agent保持一致：登录用户可查看和维护规则。后续如有角色权限要求，再单独增加管理员/业务人员的维护边界。

## 9. 开发分期与验收

### 第一阶段：规则基础与页面（已完成）

1. 从旧编码规范初始化PP码段字典与基础映射。
2. 建立PP规则数据模型、每日备份和修改记录。
3. 建立PP规则配置入口、基础规则页、客户特殊规则页和默认占位说明。
4. 验收：业务可不改Excel，在页面新增、编辑、停用和查询PP规则。

### 第二阶段：单条PP转码（原型已完成）

1. 识别PP规格并解析胶系、玻布、长度、树脂含量和配方类别。
2. 匹配PP基础规则与客户特殊规则，生成27位码。
3. 输出字段证据、评分和待人工确认码值；首期不输出正式码。
4. 验收：用已确认样例逐码段核对，未维护字段按规范输出对应数量星号。

单条转码已统一通过任务引擎执行，不再使用独立即时计算链路；因此与批量转码使用相同的规则版本、证据生成、人工确认和任务追溯逻辑。

### 第三阶段：批量与人工确认（已完成）

1. 支持上传PP转码Excel。
2. 生成任务、逐行确认中心、下载结果。
3. 支持“本次确认”及“暂不处理”；业务明确勾选、填写业务依据和触发条件后，才可保存为当前客户的长期规则。
4. 验收：批量任务全程可追溯，未确认项不写入正式码，确认后也不写入正式码。

## 10. 当前实现与测试（2026-08-11）

- 已建立PP自有基础规则、PP客户特殊规则、修改记录和每日备份存储；仅胶系共享营销转码Agent当前活动胶系主表及兼容别名，不改动CCL营销转码规则。
- 已建立`PP转码Agent`单条页面、`PP转码Agent规则维护`页面及内部单条转码接口。
- PP首页和确认中心已按营销转码Agent的信息架构统一：单条/批量共用任务列表和日志，确认中心采用左侧记录导航、右侧逐条确认。
- 已初始化明确格式规则：玻布`106 -> 0106`，以及`50M -> 050M`等PP长度格式。胶系不再复制到PP规则库；PP转码实时使用营销转码Agent当前活动胶系主表和兼容别名，页面只读展示并跳转到统一维护入口。
- 营销转码Agent中的CCL专属胶系选择规则不会被PP继承；PP客户条件继续通过PP客户特殊规则维护。
- 所有单条结果固定返回`待人工确认`，`formal_code`始终为空；生成的27位值仅放在`pending_code`/待人工确认码值中。
- 已完成服务、接口与页面冒烟测试：输入`NY2150 玻布106 350M RC42%`可生成长度为27位的待人工确认码值，玻布段为`0106`、长度段为`350M`、树脂段为`420`，无正式码输出；已兼容该类字段相邻的常见规格写法。
- 已完成批量链路：上传Excel后识别“PP客户规格”“客户规格”或“规格”列，生成任务、逐行待人工确认记录和结果下载文件。下载文件会同步显示“待人工确认 / 本次已确认 / 暂不处理”进度，并保留“PP待人工确认码值”和“PP本次确认码值”，但不会回写正式码。
- 人工确认时业务可以调整本次27位码值；原待人工确认码值、业务本次确认码值和确认依据都会保留，供后续追溯。
- 已新增PP自动化回归测试，覆盖：单条只返回待人工确认码值且`formal_code`为空、未维护客户字段按固定码位输出星号、人工确认值只写入“PP本次确认码值”而不产生正式码。
- 已完成确认沉淀闭环：业务仅在显式勾选、填写确认依据、目标字段、规则结果和触发条件后，才能将本次确认保存为当前客户的长期PP特殊规则；未勾选时不会新增规则。
- 已完成规则分页：基础规则和客户特殊规则均支持关键词、字段分类、状态筛选与分页，避免业务在长列表中逐条滚动查询。
- 待补充：首批PP客户特殊规则、PP配方类别映射、PP客户码/GT长短秒等客户专用规则。配方类别暂未按现有CCL口径自动初始化，因为PP文档示例与现有CCL类别口径存在待确认差异。

## 11. 业务确认项

以下内容在编码结构上已明确，首期直接按本文执行：

- 玻布规格`106`按4位输出`0106`。
- 默认星号按码位长度补齐。
- 胶系复用当前胶系识别口径；配方类别复用当前胶系类别口径。
- 客户规格中的玻布、长度、树脂含量属于行业通用值，识别后直接带入编码。

以下内容需在开始第二阶段前逐项补充或在页面维护：

1. PP客户特殊规则的首批客户与明确规则内容（当前无首批规则，先建设页面维护能力）。
2. 树脂含量、卷长、玻布规格的异常写法范围，例如`RC42%`、`42.0%`、`300米`等。
3. 是否需要接入订单备注语义标准化；如需要，模型只将口语转为页面已有条件，不直接生成编码。
4. 后续是否开放“全部字段明确后自动正式出码”；首期一律人工确认。

## 12. 验收基线

- PP规则运行时不依赖任何Excel文件。
- 新增、编辑、停用PP规则后立即影响PP转码，不影响CCL转码。
- 每个27位码段可说明“来自哪条规则、客户规格直接识别或默认星号”。
- 不存在规则时按规范补星，不猜测客户专用码。
- 首期所有PP结果仅输出待人工确认码值，不输出正式码；评分仅用于展示字段确定性。
- 规则每日备份、保存30天，修改记录可追溯。
