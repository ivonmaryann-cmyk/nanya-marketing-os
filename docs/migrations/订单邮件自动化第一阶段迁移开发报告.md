# 订单邮件自动化第一阶段迁移开发报告

## 范围和结论

本阶段仅为迁移计划列出的20张订单邮件自动化表建立开发准备和迁移验证能力。应用默认数据库仍为SQLite，未执行正式读写切换，未迁移或删除历史附件，未修改业务页面、邮件分流、录单模板字段或业务判断。

当前状态：DB-01至DB-11、FS-01已完成代码开发并进入待验证；DB-12至DB-15、DB-17只有后续设计或前置能力，尚未实施；DB-16、DB-18、FS-02至FS-06未开始。

## 已实现能力

- PostgreSQL 16本地Compose配置、环境变量配置、`psycopg`连接池、超时和事务回滚。
- 自动化模块独立数据访问入口；默认继续委托SQLite。
- `0001_automation_schema.sql`版本迁移、SHA256防篡改记录和20张表DDL。
- 参数绑定、Identity/`RETURNING`、`ON CONFLICT`、`STRING_AGG`和自动化元数据方言兼容。
- SQLite在线备份快照、按依赖顺序幂等Upsert、保留主键、序列重置和失败整批回滚。
- 行数、主键集合、逐行规范化哈希、唯一键、逻辑外键、附件大小/SHA256和模板数据核对。
- 文件存储接口及“新对象键优先、旧路径回退”的双读；未搬迁、覆盖或删除文件。
- JSON和Markdown迁移报告；错误报告只记录异常类型，不输出连接串、授权密文或正文。

## 尚未完成和阻塞

- 本机没有Docker、`psql`或可用的`AUTOMATION_TEST_DATABASE_URL`，因此空库DDL、重复全量导入、数据库回滚和SQLite/PostgreSQL双后端业务矩阵尚待真实PostgreSQL验证。
- 本地SQLite样本的邮件、附件、案例和模板业务数据均为0，只能验证结构、默认规则和审计工具，不能替代生产数据核对。
- DB-12增量同步、DB-13连续7天影子比较、DB-14性能并发、DB-15准入、DB-17切换回滚和DB-18稳定观察需后续阶段。
- FS-02至FS-06涉及对象存储写入、历史附件复制、连续验证和正式切换，按要求未实施。
- 全量测试保留一个迁移前已存在的失败：录单模板测试将“不含税单价”误匹配到“单价”。本阶段未修改该业务逻辑。

## PostgreSQL本地启动

在本地未跟踪的环境文件中设置`POSTGRES_PASSWORD`，然后执行：

```powershell
docker compose -f compose.postgres.yaml --env-file .env.postgres.local up -d
docker compose -f compose.postgres.yaml ps
```

测试连接应指向隔离的测试数据库，不得指向生产库。

## 迁移与校验命令

```powershell
python -m fangzheng_web_app.automation_migration audit-sqlite --sqlite storage/app.db --report outputs/migrations/sqlite-audit.json
python -m fangzheng_web_app.automation_migration migrate --sqlite storage/app.db --test-target --report outputs/migrations/test-migration.json
python -m unittest tests.test_automation_migration_infrastructure tests.test_automation_postgresql_integration
```

正式环境迁移不得自行执行；必须先确认目标连接、备份、维护窗口和审计结果。

## 回滚命令

仅隔离测试库允许结构清理，且要求固定确认词：

```powershell
python -m fangzheng_web_app.automation_migration rollback-test-target --confirm DROP-AUTOMATION-TEST-DATA
```

应用侧回滚方式是保持或恢复`AUTOMATION_DATABASE_BACKEND=sqlite`。该操作不修改SQLite数据。生产目标库禁止使用测试清理命令。

## 现有功能影响评估

风险较低但仍需集成验证。默认配置继续走原SQLite，现有接口和页面未改；附件读取增加旧路径兼容回退。只有显式把自动化后端改为PostgreSQL才会启用新连接，因此本阶段不得在生产修改该开关。
