# 订单邮件自动化第二阶段影子迁移开发报告

## 范围和结论

本阶段仅实现DB-12至DB-15的开发工具和本地验证：可靠增量同步、后台影子比较、只读并发基准和切换准入检查。未执行DB-16正式切换，页面和接口仍只返回SQLite结果，未迁移附件，未删除或覆盖SQLite数据。

当前DB-12至DB-15均为“待验证”。没有真实PostgreSQL实例、代表性数据、连续7天观察、已批准性能阈值和人工验收证据，因此不得进入正式切换。

## DB-12 可靠增量同步

- SQLite为20张业务表建立事务内Outbox触发器；自动化种子元数据单独过滤同步。
- Outbox只记录事件ID、表、操作和主键，不记录邮件正文、附件、模板内容或授权密文。
- PostgreSQL使用Inbox事件ID实现幂等消费。
- 每批复用一个PostgreSQL连接，每个事件独立事务，按Outbox ID顺序处理。
- PostgreSQL失败时SQLite业务事务不受影响；同步器记录异常类型、重试次数和指数退避时间，并停止在首个失败事件。
- 恢复后可使用常驻轮询自动补齐积压。

## DB-13 影子读比较

- 影子比较作为后台命令运行，不接管页面响应。
- 比较邮件日期计数、分类计数、列表排序、案例闭环、规则、关键词、模板、版本和附件元数据。
- 本地只记录记录数、SHA256、耗时和是否一致，不记录原始业务值。
- 支持7天观察摘要；尚未开始真实连续观察。

## DB-14 性能与并发

- 提供连接池只读并发基准，默认并发30，输出成功数、错误类型、错误率、P50、P95和最大耗时。
- 项目负责人尚未批准具体阈值，真实测试未执行。
- 修改分流、模板等写入并发场景必须在隔离测试库和代表性数据准备完成后执行，本阶段没有向现有数据写入压测数据。

## DB-15 准入检查

- 准入检查默认拒绝，所有证据必须显式为通过。
- 强制要求至少7天影子观察、未解释差异为0、Outbox积压为0、性能阈值获批且测试通过。
- 示例证据当前返回16个阻塞项，退出码为2。

## 环境变量

- `AUTOMATION_SHADOW_DATABASE_URL`
- `AUTOMATION_OUTBOX_BATCH_SIZE`
- `AUTOMATION_OUTBOX_POLL_SECONDS`

连接串只允许放在环境变量或本地未跟踪配置中。

## 运行命令

先在隔离PostgreSQL目标完成第一阶段迁移，再运行：

```powershell
python -m fangzheng_web_app.automation_migration outbox-status --sqlite storage/app.db
python -m fangzheng_web_app.automation_migration sync-outbox --sqlite storage/app.db --batch-size 100 --watch --poll-seconds 5
python -m fangzheng_web_app.automation_migration shadow-compare --sqlite storage/app.db --report outputs/migrations/shadow-daily.json
python -m fangzheng_web_app.automation_migration shadow-summary --sqlite storage/app.db --days 7
```

隔离测试库只读性能测试：

```powershell
python -m fangzheng_web_app.automation_migration benchmark-read --concurrency 30 --iterations 5 --report outputs/migrations/read-benchmark.json
```

准入检查：

```powershell
python -m fangzheng_web_app.automation_migration preflight --evidence config/automation_preflight.example.json --report outputs/migrations/preflight.json
```

## 停止与回滚

停止影子同步器即可回滚第二阶段运行，不影响SQLite业务。前台运行时使用 `Ctrl+C`；作为计划任务、服务或容器运行时，只停止对应的同步任务，不批量停止其他Python进程。Outbox保留未处理事件，恢复同步器后继续处理。
