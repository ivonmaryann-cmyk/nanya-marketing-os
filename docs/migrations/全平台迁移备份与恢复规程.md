# 全平台 PostgreSQL 迁移备份与恢复规程

> 适用范围：`nanya-automation-dev` 开发环境的全平台正式迁移。
> 关联台账：`全平台统一PostgreSQL实际迁移执行计划.md`。
> 生效日期：2026-08-27。

## 1. 责任与保留

| 角色 | 责任 |
|---|---|
| 执行人 | Codex：执行备份、生成 SHA256、运行迁移和对账；不删除来源数据 |
| 业务确认人/恢复责任人 | ny：确认维护窗口、来源停写、恢复验证和业务验收 |
| 数据库侧支持 | 开发 PostgreSQL 管理员：保障目标库可用、账号权限和服务器级备份（如有） |

- 来源 SQLite、本机 Docker PostgreSQL、源文件和本次备份至少保留 **30 天**；
- 备份目录为 `backups/platform-migration/<迁移批次>/`，不提交 Git；
- 备份清单、时间、SHA256、行数、操作者写入 `outputs/migrations/`，不记录密码或完整连接串；
- 未经 ny 书面确认，禁止删除来源库、目标库中的迁移现场或备份文件。

## 2. P3 执行时必须生成的备份

| 对象 | 方法 | 完成证据 |
|---|---|---|
| SQLite `storage/app.db` | SQLite 一致性在线备份（`Connection.backup`） | `.sqlite3` 文件、SHA256、`PRAGMA integrity_check=ok` |
| 本机 Docker PostgreSQL `nanya_automation` | 容器内 `pg_dump --format=custom` | `.dump` 文件、SHA256、`pg_restore --list` 成功 |
| 目标开发库 | 迁移前 schema/表数快照；若非空则先 `pg_dump --format=custom` | 目标库基线报告、备份文件（如适用） |
| 文件索引指向的邮件、附件、Excel/PDF | 只读路径、大小、哈希审计 | 文件异常清单与统计报告 |

## 3. 恢复演练与回退原则

1. 迁移前只验证备份可读；P5 失败时不切换应用，来源库继续作为运行来源。
2. 目标库迁移失败：保留现场供排查，不清空、不覆盖来源；由 ny 确认后才允许重建测试目标对象。
3. PostgreSQL 恢复演练应恢复到**临时数据库或临时 schema**，不得覆盖来源或已验收的目标库。
4. SQLite 恢复演练应恢复为临时副本，执行完整性检查和关键表行数核对。
5. P6 对账不通过、P8 业务验收阻塞时，按 P7 将应用统一后端切回 SQLite/原来源；不自动回放或覆盖任何数据。

## 4. P3 放行条件

只有以下项目全部完成，才可从 P3 进入 P4/P5：

- 维护窗口内 Flask、邮件同步、订单抓取、转码等写入任务已停止；
- SQLite 与本机 PostgreSQL 备份均可读，SHA256 已记录；
- 目标库基线已记录；
- 源/目标表行数、主键范围与文件索引审计已输出；
- ny 确认备份完成与恢复责任。
